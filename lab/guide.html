const sampling = {
  domain: placement, address: 'zero', filter: 'anisotropic',
};
const coverage = scalar.image(controls, {...sampling, channel: 'r'});
const deposited = scalar.image(controls, {...sampling, channel: 'g'});
const polished = scalar.image(controls, {...sampling, channel: 'b'});

const inked = surface.coat(base, color.srgb('#214c67'), coverage);
const finished = surface.channels(inked, {
  roughness: scalar.add(.68, scalar.multiply(-.28, polished)),
});
const result = surface.bump(finished, scalar.multiply(.0016, deposited));

The deposition channel already contains coverage × height. Filtering their product retains correlation that would be lost by multiplying separate averages: F(a × b) ≠ F(a) × F(b). The filtered deposition goes directly into bump.

PolicyReconstructionRead ceiling
linearBase-level bilinear; the original default4
trilinearBlend adjacent mip levels selected by the pixel footprint8
anisotropicUp to eight taps along the footprint's principal major axis64

R, G and B share one reconstruction when image, placement, address and filter match. The shader derives its footprint before addressing. CPU callers supply footprint: {dx, dy} separately from their derivative directions; omitting it asks for a point query. Partials hold footprint and filter configuration fixed.

Zero addressing keeps finite marks finite. Coarse levels continue widening and attenuating after the stored 1 × 1 mip, so a very small mark fades instead of spreading a constant mean. The eight-tap approximation has a defined cost ceiling; it is not an exact pixel integral. The original facet atlas keeps its own filtering policy.

01 / Compose

A skin with an ivory underside

Two paints share one sampled field. A facing mask places the second paint over the lower surface. The complete expression still uses four texture reads per fragment.

import {facets, surface, scalar, named, splitRecipe, materialGraph}
  from '@moonweave/surfaces/core';
import {createTexturingSystem, bindSurfaceCoordinates}
  from '@moonweave/surfaces/three';

const field = named('bodyField', facets(splitRecipe('carapace').mapping));
const skin = named('bodyPaint', surface.paint(field, 'carapace'));
const ivory = surface.paint(field, 'horn');
const underside = named('transition', scalar.ramp(
  scalar.facing([0, -1, 0]), -.25, .65,
));
const strength = named('strength', scalar.parameter(.9));

const graph = materialGraph(surface.mix(
  skin, ivory,
  scalar.multiply(underside, strength),
));

const system = createTexturingSystem(THREE);
const handle = system.createMaterial(graph, {
  coordinates: 'attribute',
});
bindSurfaceCoordinates(THREE, mesh.geometry);
mesh.material = handle.material;

handle.patch({strength: {value: .5}});
// Reuses the compiled structure and updates the changed uniform.

The host supplies Three, its mesh, lights and animation. The package contains no bundled renderer. Install the downloaded TGZ with npm install ./moonweave-surfaces-{{VERSION}}.tgz. TypeScript users also install @types/three matching their engine revision. When copying ESM files directly, keep the shared chunks/ directory beside the entry modules.

Color and procedural fields

A material without a painted atlas

A noise field can drive both color and finish. Reusing the same expression shares one procedural evaluation. The Procedural stone example has no paint or facet nodes:

import {color, domain, materialGraph, named, patchGraph, scalar, surface}
  from '@moonweave/surfaces/core';

const frame = named('stoneSpace', domain.transform([
  3.2, 0, 0, 0,  0, 3.2, 0, 0,
  0, 0, 3.2, 0,  0, 0, 0, 1,
]));
const grain = named('stoneGrain', scalar.noise({
  seed: 37, domain: frame,
}));
const shade = named('stoneShadow', color.srgb('#484653'));
const light = named('stoneLight', color.srgb('#c5bbc4'));
const pigment = color.mix(shade, light, scalar.ramp(grain, .28, .72));
const stone = surface.channels(surface.material(pigment), {
  roughness: scalar.add(.32, scalar.multiply(.42, grain)),
});
const graph = materialGraph(stone);

// Colors are stored and mixed in linear RGB.
const next = patchGraph(graph, {
  stoneGrain: {seed: 84},
  stoneShadow: {value: color.srgb('#538fb3').value},
});

color.linear([r,g,b]) accepts extended linear RGB coordinates. Out-of-gamut intermediates remain available to later operations; material inputs project the result to reflectance. color.srgb('#rrggbb') decodes an sRGB color once, when authored. color.mix blends those linear colors using a clamped scalar mask. surface.material(color) provides a neutral finish; surface.channels connects scalar fields to roughness, metalness, clearcoat or opacity.

Open Procedural stone in Compose to edit its colors, variation, tone boundary and finish. Expand stoneSpace to change the coordinate scale or offset. In Lichen on shell, one noise field controls green pigment and where it covers the original carapace paint. Its mask is a custom expression: choosing Position or Surface direction replaces that mask while preserving the field still used by the color.

Noise is point sampled. Its analytic derivatives describe local change; they do not automatically filter fine detail. High frequencies can alias and need a separate filtering strategy. The GPU noise implementation requires WebGL2 / GLSL ES 3.

A graph with no live facet samples performs no atlas reads and does not allocate the paint textures. Its procedural evaluation still has arithmetic cost. The graph inspector reports facet samples, procedural evaluations and texture reads separately.

Fields applied to a surface

Give a field depth

Carved porcelain uses one procedural field for pigment, polished finish and engraved detail, without a painted atlas. Weathered shell applies the same construction to the original carapace facets. The field remains one shared expression:

const grain = scalar.noise({seed: 73});
const carving = scalar.ramp(grain, .4, .68);
const depth = named('depth', scalar.parameter(-.035));
const porcelain = surface.bump(
  surface.channels(surface.material(color.mix(
    color.srgb('#eee5cf'), color.srgb('#40596d'), carving,
  )), {
    roughness: scalar.add(.28, scalar.multiply(.28, carving)),
  }),
  scalar.multiply(depth, carving),
);

In Compose, Height detail lists each application. + Add height detail creates a grain field and an adjustable signed amplitude, or applies the field selected in New detail field. Negative amplitudes engrave; positive amplitudes raise the shading. Each application can use another Height expression or be removed. Undo restores the previous graph.

Open Connect finish fields to connect that field to roughness, metalness, clearcoat or opacity. Choose New adjustable value for an independent control, or Inherit surface to remove an override. Values still used by another part of the composition stay connected.

Compose a mask with the height before applying it: bump(surface, multiply(mask, height)) includes the changing mask's contribution to the slope. relief(surface, mask) scales an existing slope instead. Height detail changes shading; the mesh, silhouette and geometric shadows keep their original shape.

The renderer computes height differentials only along the paths that need them. A spatially constant height adds no detail and compiles away. An editable amplitude currently at zero keeps its program, so a slider can cross zero without rebuilding the shader.

A palette with relationships

Ink & ivory groups dark blue-gray planes over a quiet ground, with sparse warm accents. Patinated brass places broad verdigris deposits and an exposed scrape. Each study derives related pigments from one source color. Marks change color while the painted relief and finish keep their own controls.

const pigment = named('pigment', color.oklch([.62, .08, 220]));
const shadow = color.adjust(pigment, {
  lightness: -.18, chroma: .65, hue: 12,

const accent = color.adjust(pigment, {
  hue: named('accentHue', scalar.parameter(155)),

Lightness is an offset, chroma a multiplier, and hue a rotation in degrees. Each may be a shared or spatial scalar field. Palette and value controls come first; open Field construction for masks, transitions, grain and coordinates.

The chisel is a finite coverage stamp in local [-1,1]³. Its domain places and stretches it; feather is measured in those local units. It uses existing scalar operations. Coverage changes roughness or height only when you connect it there. Smooth edges are point sampled and still need filtering when details become smaller than a pixel.

Reusable field programs

A field can stand on its own

Store, edit and sample a scalar, color or coordinate field directly. The same graph format also carries facet and surface expressions. CPU sampling covers the first three types; surface rendering belongs to the adapter.

import {scalar, surface, named, materialGraph, expressionGraph, graphExpression,
  instantiate, createFieldSampler, serializeGraph, parseExpressionGraph, patchGraph}
  from '@moonweave/surfaces/core';

const field = expressionGraph(named('grain', scalar.noise({seed: 17})));
const sample = createFieldSampler(field);
const atPoint = sample({
  position: [.2, .4, .7],
  dx: [.01, 0, 0], dy: [0, .01, 0],
});
// atPoint contains value, dx and dy.

const restored = parseExpressionGraph(serializeGraph(field));
const changed = patchGraph(restored, {grain: {seed: 29}});
const sampleChanged = createFieldSampler(changed);

// Bring the stored field back into another surface composition.
const imported = graphExpression(restored);
if (imported.kind !== 'noise') throw new TypeError('Expected the saved noise field.');
const reused = instantiate(imported, {prefix: 'shell'});
const shell = materialGraph(surface.bump(surface.paint('carapace'),
  scalar.multiply(.025, reused)));

Preparing a sampler resolves the graph once. Each call receives its own sample context. materialGraph and parseGraph continue to require a surface for the renderer and atelier. foldGraph interprets any root with your own typed algebra.

graphExpression preserves the selected root's reachable sharing and names. Its result can be placed or instantiated like any authored expression. Unused document definitions stay in the original graph and are omitted from the returned expression.

03 / Edit deliberately

Constants specialize. Parameters stay editable.

A fixed fact

scalar.constant(0)
surface.mix(a, b, 0)

A literal zero can eliminate the second branch and its sampled fields. Changing the literal may create a different program.

A live control

scalar.parameter(0)
scalar.parameter(1)

Both values use the same program structure. The compiler retains the branch so a control can move through zero without rebuilding the shader.

Whole graphs are immutable. Use handle.patch(changes) for values, or pure patchGraph(graph, changes) followed by handle.setGraph(next). Unchanged nodes, compiled structure and uniform containers retain their identity. Use named(id, expression) to expose a stable ID on any expression. Reuse that returned value to share a node; independent expressions need distinct names. Each patch targets those authored IDs:

handle.patch({
  strength: {value: .6},
  transition: {low: -.4, high: .7},
  bodyField: {scale: .22},
  bodyPaint: {style: {roughness: .7}},
});

// When the scene no longer uses these materials:
system.dispose();

A name survives JSON and value edits without changing the shader. It does not turn a constant into a parameter. References, literal constants and node kinds are structural edits. Build a new graph for those. The atelier follows the same distinction: paints and blends remain separately selectable, and changing a control preserves the existing composition.

Composition law

Later finish values take precedence.

A finish override is a map from channel names to scalar expressions. Its composition has a simple law:

channels(channels(surface, A), B)
= channels(surface, { ...A, ...B })

The compiler combines adjacent overrides and removes scalar work that has become completely hidden. The editable document retains that work, and an inner surface used elsewhere remains intact. Empty overrides are identities. This law does not rearrange scalar arithmetic.

The same precision applies to masks. Changing a recognized Position region to Surface direction preserves its strength and ramp bounds. Reversing the entire mask keeps 1 − amount × region distinct from amount × (1 − region). Shared masks retain their other users.

04 / Follow the creature

Join parts in one rest frame

For a multipart creature, store each part's positions and normals in a common frame before deformation. The texture follows the stored rest coordinates.

creature.updateWorldMatrix(true, true);
const inverseRoot = creature.matrixWorld.clone().invert();

creature.traverse(object => {
  if (!object.isMesh) return;
  const toRoot = inverseRoot.clone().multiply(object.matrixWorld);
  bindSurfaceCoordinates(THREE, object.geometry, {matrix: toRoot});
  object.material = handle.material;
});

Use separate geometry objects when shared geometry instances need different rest frames. Domain transforms use the inverse transpose for normals and the linear transform for position differentials. Scalar evaluation exposes analytic first differentials for inspection and testing.

Reusable compositions

Local controls. Shared inputs.

A reusable composition can be an ordinary JavaScript function. When reusing a named expression template, instantiate copies its local values and gives their authored IDs a deterministic prefix. Explicit shared inputs and their descendants retain identity. Shared inputs must be immutable expressions made by the constructors or named helpers. Construct a shared value once before placing it in the template.

import {instantiate, inDomain} from '@moonweave/surfaces/core';

const left = instantiate(inDomain(template, leftFrame), {
  prefix: 'left', shared: [globalDepth],
});
const right = instantiate(inDomain(template, rightFrame), {
  prefix: 'right', shared: [globalDepth],
});

Here template is an authored composition, leftFrame and rightFrame place it, and globalDepth is a parameter already used by that template. A local grain becomes left_grain or right_grain. Editing the shared depth affects both; editing a local grain affects its own instance. Reusing a prefix still creates a naming conflict when independent instances are combined, and validation reports it.

Instancing controls ownership. inDomain controls coordinates. Sharing an input does not pin its position against a later domain transform.

07 / Know the boundary

A precise foundation

The supplied renderer adapter uses Three's WebGLRenderer. The pure core is independent of it. A WebGPU, MaterialX, texture-baking or offline renderer would need its own backend.

The 512² atlas pair occupies about 2.67 MiB with mipmaps when a graph needs it. Pure color and procedural graphs allocate no atlas. A material graph may use up to eight facet samples and sixteen paint styles. Embedded images use float32 mip data with explicit linear, trilinear or bounded anisotropic reconstruction; up to six resources can accompany the atlas pair. Filtered read counts are ceilings, and the displayed costs describe graph work rather than hardware frame rate.

Six graph types and twenty-six operations share one typed signature for value and reference rules. foldGraph exposes a memoized interpretation of that graph for another backend or analysis. The atelier itself uses Solid and TypeScript, with Effect scopes for graphics and browser resources; none is required by the reusable surface package.

Authored relief is shading, not displaced geometry. Surface mixes are not physical layered optics. CPU evaluation checks scalar fields, colors and domains, including procedural noise and image fields. It does not reproduce lighting or atlas sampling. The complete contracts, research and verification are included with the source.
